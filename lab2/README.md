# Лабораторная работа №2
## Проектирование информационной системы
## 1. Описание предметной области
Предметной областью является деятельность гостиничного предприятия по управлению номерным фондом. Основные бизнес-процессы включают ведение учёта номеров, управление категориями и тарифами, обработку запросов на бронирование, регистрацию проживающих гостей и расчёты за проживание.
В настоящее время учёт номерного фонда и обработка заявок ведутся разрозненно: часть информации хранится в бумажных журналах на ресепшн, часть — в электронных таблицах. Это приводит к двойным бронированиям, потере данных о гостях и низкой скорости обслуживания.
Цель системы — исключение двойных бронирований за счёт автоматического контроля занятости номеров, создание единой базы гостей с историей проживания, автоматизация операций бронирования, заселения и выселения.
## 2. Пользователи и роли
Администратор | Сотрудник ресепшн, управляет операциями с номерами | Поиск свободны номеров, оформление бронирований, заселение, выселение, изменение статуса номера, регистрация гостей | Поиск номеров по датам и вместимости; создание и отмена броней; заселение и выселение; расчёт стоимости; просмотр календаря загрузки; регистрация гостей; проверка дубликатов
Гость | Клиент отеля, бронирует номер | Регистрация в системе; просмотр каталога номеров и цен; создание брони; отмена своей брони; просмотр истории своих бронирований
Персонал | Сотрудник, ответственный за уборку номеров | Просмотр списка номеров, требующих уборки; отметка номера как готового для заселения
## 3. Сценарии использования
### Сценарий 1. Поиск свободных номеров
Инициатор: Администратор
Пошаговое описание:
Администратор открывает раздел «Поиск номеров».
Указывает дату заезда и дату выезда.
Указывает количество гостей.
При необходимости выбирает категорию номера.
Система анализирует занятость номеров на указанный период.
Система формирует список свободных номеров с ценами.
Администратор просматривает результаты.
Ожидаемый результат: Получен список свободных номеров, подходящих под запрос, с указанием стоимости проживания.
### Сценарий 2. Создание бронирования
Инициатор: Администратор (или Гость)
Пошаговое описание:
Пользователь выбирает свободный номер из результатов поиска.
Система открывает форму бронирования.
Пользователь указывает данные гостя (ФИО, паспорт, телефон, email).
Система проверяет наличие дубликата гостя по паспортным данным.
Если гость найден — данные подставляются автоматически; если нет — создаётся новая запись.
Пользователь подтверждает даты заезда и выезда.
Система рассчитывает предварительную стоимость.
Пользователь подтверждает создание брони.
Система сохраняет бронь и помечает номер как занятый на указанный период.
Ожидаемый результат: Создано бронирование, номер закреплён за гостем на указанные даты, исключено двойное бронирование.
### Сценарий 3. Заселение гостя
Инициатор: Администратор
Пошаговое описание:
Администратор открывает раздел «Заселение».
Находит бронирование по ФИО гостя или номеру брони.
Система отображает данные брони и гостя.
Администратор проверяет документы гостя.
При необходимости корректирует данные гостя.
Администратор подтверждает заселение.
Система создаёт запись о проживании.
Система меняет статус номера на «Занят».
Ожидаемый результат: Гость заселён, создана запись проживания, статус номера обновлён.
### Сценарий 4. Выселение гостя
Инициатор: Администратор
Пошаговое описание:
Администратор открывает раздел «Выселение».
Находит активное проживание по номеру или ФИО гостя.
Система отображает данные проживания и дату фактического выезда.
Система автоматически рассчитывает итоговую стоимость проживания.
Администратор проверяет расчёт.
Администратор подтверждает выселение.
Система закрывает запись проживания.
Система меняет статус номера на «Требует уборки».
Ожидаемый результат: Гость выселен, итоговая сумма рассчитана, номер переведён в статус «Требует уборки».
### Сценарий 5. Отмена бронирования гостем
Инициатор: Гость
Пошаговое описание:
Гость авторизуется в системе.
Открывает раздел «Мои бронирования».
Выбирает бронь, которую хочет отменить.
Система отображает детали брони.
Гость нажимает «Отменить бронирование».
Система запрашивает подтверждение отмены.
Гость подтверждает отмену.
Система меняет статус брони на «Отменена».
Номер автоматически освобождается на указанный период.
Ожидаемый результат: Бронь отменена, номер освобождён и доступен для новых бронирований.

## 5. Компоненты системы
Веб-интерфейс | Предоставление пользовательского интерфейса для администратора, гостя и персонала
Серверная часть | Обработка логики: заселение, выселение, бронирование
База данных | Хранение данных о гостях, номерах, категориях, бронированиях, проживаниях
Система аутентификации | Авторизация пользователей, разграничение прав доступа
Система уведомлений | Отправка email/sms о подтверждении брони
## 6. Диаграмма компонентов.
Находится в diagrams/
Пользователи (Администратор, Гость, Персонал) — внешние актёры, взаимодействующие с веб-интерфейсом.
Веб-интерфейс (Frontend) — отправляет HTTP-запросы к Backend.
Серверная часть (Backend) — обрабатывает запросы, взаимодействует с БД через SQL, с системой аутентификации и системой уведомлений.
База данных — хранит все данные системы, принимает SQL-запросы от Backend.
Система аутентификации — проверяет учётные данные, взаимодействует с Frontend и Backend.
Система уведомлений — получает задачи от Backend и отправляет email/SMS через внешний шлюз.
## 7. Концепция информационной системы.
Назначение и цель. Информационная система предназначена для автоматизации основных бизнес-процессов гостиницы: управления номерным фондом, обработки бронирований, регистрации гостей, оформления заселения и выселения. Цель — исключить двойные бронирования, создать единую базу гостей и ускорить обслуживание.
Основные возможности:
ведение единой базы номеров и их категорий;
ведение единой базы гостей с историей проживания;
оформление и отмена бронирований;
оформление заселения и выселения гостей;
автоматический расчёт стоимости проживания;
формирование отчётов по загрузке и доходам;
самостоятельное бронирование номеров через веб-портал.

Основные компоненты и их взаимодействие:
Пользователь через браузер обращается к веб-интерфейсу.
Веб-интерфейс отправляет HTTP/REST-запросы к серверной части.
Серверная часть проверяет права доступа через систему аутентификации.
Backend выполняет бизнес-логику и обращается к базе данных через SQL.
При необходимости Backend инициирует отправку уведомлений через систему уведомлений и внешний Email/SMS-шлюз.
Результат возвращается пользователю через веб-интерфейс.
